# FTA分析支援ツール UI再設計ブリーフ（Claude Design向け）

## 1. 目的と主要作業

FTAの頂上事象に対し、AI候補と人の判断を組み合わせて一〜三次要因を深掘りし、根拠・直接要因評価・再発防止策を記録するWebツールである。主要作業は「分析作成」「参考情報の整備」「AI生成または手動追加」「候補の評価・深掘り」「3表現で確認」「出力」である。

根拠付き仕様、状態、判断保留は [現行画面・操作仕様](ui-current-spec.md) を正とする。本書は仕様の置換ではない。

## 2. 維持必須の機能とデータ意味

1. 分析一覧の参照、新規作成、改名、編集、確認付き削除、JSON/CSV/Markdown出力。
2. 頂上事象と、AIへ渡す2種の分析context（システム構成・対象範囲／障害発生時の状況・観測事実）の区別。入力中と保存済みの区別。
3. **通常生成**（一次全体、次階層はYesの全親）、**追加生成**（一次または特定親）、**手動追加**を識別できること。AI/手動の出自も保持する。
4. 階層、親子、要因title/description/memo、表示順、warning。頂上事象はNodeではない。
5. **Yes/No/未評価**と、別軸の**5値の直接要因評価**、comment/evidence/prevention。両者を統合しない。
6. カード編集、階層tree、一覧表の3表現。現行filterはカードと表が対象。
7. 空、生成中、新要因なし、全候補品質除外、warning付き保存、一部/全体/通信失敗を判別できるfeedback。全除外と「AI応答0件」を同一視しない。
8. 親要因削除時の子孫削除警告、分析削除時の全関連データ削除警告。

## 3. 配置・見せ方を変更できる領域

- header/navigation/CTAの位置、情報階層。
- 一覧のtable/card、編集のcolumn構成、折りたたみ、modal/drawer/inline editorの選択。
- 階層、AI/手動、評価、直接要因、品質warningの視覚表現。ただし意味の差は維持する。
- toast、inline message、progress、親ごとの結果表示方式。ただし状態を減らさない。
- viewport別layout、段階的開示、文言の明瞭化。

### 改善仮説（確定要求ではない）

- 生成が「一括/特定親」と「通常/追加/手動」の2軸にまたがるため、対象と結果を操作前後に明示すると誤操作を減らせる可能性がある。
- カード/tree/表でfilter範囲が異なるため、対象表現の明示または仕様統一を検討できる。
- 長時間生成では親ごとのprogressと部分成功を残すことが有用な可能性がある。

## 4. デザインと分けて判断する仕様変更

以下はデザイナーが黙示に決めず、product/engineering/利用者の合意を要する。

- Yes/Noと直接要因5値の業務定義、生成対象への影響。
- 階層数、親子関係、通常/追加生成の対象・件数、品質gate、自動保存timing。
- 出力項目/形式、削除cascade、更新日時の定義。
- filterをtreeにも適用するか、非表示要因を一括生成対象から外すか。
- 現行仕様書で「不具合の疑い」としたinline保存/error表示を修正するか。現行挙動の無条件踏襲は不要。

## 5. 再設計時の代表シナリオ

1. **初回**: 0件一覧→手入力またはsample→作成→空の編集画面。
2. **未保存値から生成**: 頂上事象/contextを編集し保存ボタンを押さず一次生成。自動保存と対象値が明確か。
3. **評価と一括深掘り**: 一次をYes/No/未評価に分け、Yesだけから二次を順次生成。親ごとの進捗/成否が追えるか。
4. **特定親の補完**: 一親へAI追加、別親へ手動追加。AI/手動と対象を誤認しないか。
5. **評価併存**: Yes要因を「直接要因でない」とし、根拠等を保存。3表示の意味が一貫するか。
6. **結果分岐**: 正常、0候補、全除外、一部親失敗、通信失敗、warning付き保存を個別再現。
7. **多件/長文**: 全階層多数、長いtitle/description/warning。検索、横scroll、折りたたみ、位置維持。
8. **破壊操作**: 子孫付き要因と分析全体の削除、取消、失敗。
9. **出力**: 3形式の導線と形式別項目差。
