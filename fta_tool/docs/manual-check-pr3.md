# PR-3 Windows 実機確認の手順

計画書（[ui-redesign-implementation-plan.md](ui-redesign-implementation-plan.md)）第8.3節の手動確認（10項目）を、Windows の Edge・Chrome で行うための手順です。対象は **PR #18 の最新 HEAD**（PR 本文の「最新 HEAD」に書いた SHA）です。

この手順書は確認の進め方をまとめたもので、受入の合否を決めるものではありません。合否と PR #18 のマージは、利用者が判断します。

## 0. はじめに（守ること）

- **普段の DB と作業フォルダは使いません。** PR #18 のコードは別フォルダ（git worktree）に取り出します。確認用の DB は、下の手順で作る新しいフォルダにだけ置きます。アプリの DB は「起動したフォルダの `fta_tool.db`」なので、確認用のフォルダから起動します。
- **実 LLM は呼びません。** 取り出したフォルダには `.env` がないので、AI は `mock` で動きます（画面のヘッダーに「AI: mock」と出ます）。普段の `.env` は `override=True` で読み込まれ、シェルの設定より優先されます。このため、普段のフォルダからは起動しないでください。
- **不整合データは、確認用の不整合 DB にだけ作ります。** 普段の DB には作らないでください（計画 第8.3節）。
- **表示の更新の失敗と、保存・追加・削除の失敗は別のものです**（第6節）。「表示を最新にできませんでした」は、直前の保存などが完了したうえで、表示だけが更新されなかったことを示します。
- ブラウザは、Windows 11 の Edge と Chrome を使います。表示倍率 100%、ブラウザの拡大 100%、ウィンドウは最大化します（項目 7 は開発者ツールで寸法を指定します）。

以下の例では、次のフォルダを使います（別の場所でもかまいません）。

| 用途 | フォルダ（例） |
|---|---|
| PR #18 のコード | `C:\fta-check\pr3-src` |
| 確認用 DB（正常データ） | `C:\fta-check\pr3-normal` |
| 確認用 DB（不整合データ） | `C:\fta-check\pr3-anomaly` |

## 1. PR #18 の最新 HEAD を取得して確認する

PowerShell で、普段のリポジトリのフォルダから実行します。普段のフォルダの作業中の変更には触れません。

```powershell
cd C:\work\fta-202605        # 普段のリポジトリ（例）
git fetch origin claude/intelligent-noether-fcntpc
git ls-remote origin refs/pull/18/head
git worktree add --detach C:\fta-check\pr3-src origin/claude/intelligent-noether-fcntpc
cd C:\fta-check\pr3-src
git rev-parse HEAD
git status --short
Test-Path .\fta_tool\.env
```

確認すること:

- `git rev-parse HEAD` の SHA が、PR #18 本文の「最新 HEAD」と `git ls-remote` の SHA の両方と一致すること。
- `git status --short` が何も表示しないこと。
- `Test-Path .\fta_tool\.env` が `False` であること（`.env` がない）。

一致しない場合は、確認に進まずに報告してください（PR に新しいコミットが入った可能性があります）。

## 2. 確認用 DB を作る

Python は、普段アプリを起動しているもの（仮想環境）をそのまま使えます。PR-3 では `requirements.txt` を変えていません。以下では、その `python.exe` を `$py` とします。

```powershell
$py  = "C:\work\fta-202605\fta_tool\.venv\Scripts\python.exe"   # 普段の python.exe（例）
$src = "C:\fta-check\pr3-src\fta_tool"
& $py "$src\scripts\pr3_check_db.py" normal  C:\fta-check\pr3-normal
& $py "$src\scripts\pr3_check_db.py" anomaly C:\fta-check\pr3-anomaly
```

期待結果:

```text
作成しました：C:\fta-check\pr3-normal\fta_tool.db
  分析 ID 1：PR3確認：要因なし
  分析 ID 2：PR3確認：三次まで
```

不整合 DB では、「PR3確認：不整合」「PR3確認：別の分析」と出ます。

このスクリプト（`scripts/pr3_check_db.py`）は、**新しいフォルダか空のフォルダにだけ** DB を作ります。何かが入っているフォルダを指定すると「中止しました：フォルダが空ではありません」と出て、何も変更しません。作り直すときは、確認用のフォルダを削除してから実行します。

## 3. 確認用サーバーを起動する（普段の DB を使わない）

```powershell
cd C:\fta-check\pr3-normal
$env:AI_PROVIDER = "mock"
& $py -m uvicorn app.main:app --app-dir $src --host 127.0.0.1 --port 8001
```

起動時のログで確認すること:

- `dotenv file not found at C:\fta-check\pr3-src\fta_tool\.env` と出ること（`.env` がない）。
- `AI_PROVIDER = mock` と出ること。
- `Uvicorn running on http://127.0.0.1:8001` と出ること。

ブラウザで `http://127.0.0.1:8001/` を開き、分析の一覧が「PR3確認：三次まで」「PR3確認：要因なし」の2件だけであることを確認します。普段の分析が見える場合は、すぐにサーバーを止めてください（起動したフォルダが違います）。ポートを 8001 にしているので、画面の状態の保存領域（sessionStorage・localStorage）も普段の画面とは分かれます。

止めるときは、PowerShell で Ctrl+C を押します。

## 5. 別のタブで評価を変えた後の復帰（既知事項の確認）

PR-3 では、次の動作を既知事項として残しています（2026-09-30 の利用者の判断）。

- この画面で保存を確定した評価と食い違う応答は反映せず、取り直す。
- 2回続けて食い違った場合は通知し、照合用の記録を破棄する。
- その後の部分更新まで拒否し続けることはない。
- 別のタブで評価を変えた後、最初の部分更新だけ反映されない場合がある。

手順:

1. タブA で「PR3確認：三次まで」を開き、② で「一次06 バッチ処理との競合」の「Yes」を押す（「評価を更新しました」）。
2. Ctrl+T で新しいタブ（タブB）を開き、同じ分析（`http://127.0.0.1:8001/analyses/2`）を開く。タブB で「一次06」の「No」を押す（「評価を更新しました」）。
3. タブA に戻る（**再読み込みしない**）。「一次07 DB接続プールの枯渇」を選び、「詳細を編集」→ メモに「別タブ確認1」→「保存」。
   - 「保存しました」の後に、エラー「表示を最新にできませんでした。ページを再読み込みしてください。」が **1回だけ** 出る。
   - タブA の「一次06」は「Yes」のまま（表示は更新されていない）。
   - **保存は完了している**：もう一度「詳細を編集」を開くと、メモが「別タブ確認1」になっている（ダイアログはサーバーの値を読む）。
4. 開いたダイアログでメモを「別タブ確認2」にして「保存」する（手動追加など、別の操作でもよい）。
   - 「保存しました」だけが出て、新しいエラーは出ない。
   - タブA の「一次06」が「No」（タブB で変えた値）になる。以後の操作でも表示は更新される。
5. 残っているエラーの通知を × で閉じる。

3 の時点で F5 を押しても、最新の表示（一次06 は No、メモは保存済み）に戻ります。

## 6. 表示の更新の失敗と、保存・追加・削除の失敗の区別

| 通知 | 意味 | 保存・追加・削除 | 対応 |
|---|---|---|---|
| 「表示を最新にできませんでした。ページを再読み込みしてください。」 | 操作の後の表示の更新（部分更新）ができなかった | **完了している**（直前に「保存しました」「要因を追加しました」「削除しました」などが出ている） | F5 で再読み込みすると反映される。次の部分更新でも反映される（第5節） |
| 「最新の表示に更新できませんでした（理由）。入力中の内容を保存してから、ページを再読み込みしてください。」 | 表示の更新のための取得に失敗した。入力中の内容があるため、自動では再読み込みしない | **完了している** | 入力中の内容を保存してから F5 |
| （通知なしでページが再読み込みされる） | 表示の更新のための取得に失敗し、入力中の内容がないため再読み込みした | **完了している** | 選択・ステップ・タブは戻る |
| 「分析が見つかりません（削除された可能性があります）」 | 分析が別の画面で削除された | — | 一覧へ戻る |
| 「保存に失敗しました」「要因タイトルは必須です」「追加に失敗しました」「タイトルを入力してください」「削除に失敗しました」「評価を保存できませんでした：（理由）」「通信エラーが発生しました」 | 操作そのものが失敗した | **されていない** | 理由を確認してやり直す |

表示の更新の失敗が出たときは、直前に成功の通知が出ていたかを記録し、F5 の後に内容が保存されているかを確かめてください。保存の失敗としては記録しないでください。

## 7. 不整合データの確認（確認用の不整合 DB だけで行う）
